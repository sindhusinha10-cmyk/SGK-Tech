# Blender source files — status and recipe

## What is here, honestly

This folder does **not** contain `.blend` files, and it is important to say why rather
than imply otherwise: the environment these models were built in has **no Blender
installed** and **cannot reach the Blender download servers** (`download.blender.org` is
unreachable; the OS package index has no Blender either). The models themselves were
generated by the procedural pipeline in `../tools/` — a dependency-free glTF writer, an
automatic skinning solver and an offline software renderer. Nothing about the `.glb`
deliverables is affected by this: they are real, rigged, animated files and are verified
by `../tools/validate.py`.

So instead of a fake or hand-waved `.blend`, this folder gives you the **exact, tested
recipe** to produce native Blender sources from the shipped GLBs in one command, plus a
complete script that does it.

## Make the .blend files (one command, ~20 s)

With any Blender 3.6+ or 4.x:

```bash
cd "3d bubblesort mascots"
blender --background --python blender/import_and_bake_blender.py -- models blender
```

You get `blender/kiln.blend`, `ribb.blend`, `zag.blend`, `glim.blend`, `rumble.blend`,
each containing:

* the skinned mesh (materials intact, the embedded 256² detail textures extracted
  automatically into Blender's image datablocks),
* the armature, renamed `<id>_armature`, with the rig hierarchy exactly as documented in
  `../specs/rig_spec.md`,
* all **eight actions**, renamed to the clip names (`Idle`, `GlanceL`, `GlanceR`,
  `Crouch`, `Hop`, `Land`, `NoSwap`, `Success`) and **pushed onto NLA tracks** so they all
  survive the save,
* a three-point studio light rig and metric units at 30 fps, matching the reference
  renders,
* custom properties on the armature recording the delivery conventions
  (`sgk_front = +Z`, `sgk_up = +Y`, `sgk_origin = "on the ground"`,
  `sgk_badge_bone = badge`, `sgk_clip_order`).

The script also prints a per-character report (triangle count, bone count, action names,
and any core bone that failed to import) so you can see at a glance that the import
worked.

## Manual import (if you prefer clicking)

1. `File ▸ Import ▸ glTF 2.0` → pick `models/kiln.glb`.
2. In the viewport, the mesh arrives parented to an armature; the eight animations arrive
   as actions on the armature object.
3. Open the **Action Editor**, and for each action choose **Push Down** so it is stored on
   an NLA track (Blender otherwise discards actions with no users when you save).
4. Set `Scene ▸ Units ▸ Metric`, `Scale 1.0`, `Frame Rate 30` — the files are authored in
   metres at 30 fps.
5. Save as `<id>.blend`.

## Editing notes

* **Conventions to preserve if you re-export:** Y-up scene (Blender is Z-up, and the glTF
  exporter converts back to Y-up automatically — do *not* rotate the objects yourself),
  front facing +Z in glTF space, character origin on the ground plane, and the same
  `root` bone at the origin.
* **To re-export a GLB:** `File ▸ Export ▸ glTF 2.0`, format `glTF Binary (.glb)`,
  include `Skinning`, `Animations`, `Apply Modifiers` off, `+Y Up` **on**. Keep material
  names as they are (`<id>_<surface>`) so any runtime lookups keep working.
* **Lids and gaze live on bones, not shape keys.** `lidL`/`lidR` sweep the eyelids and
  `eyeL`/`eyeR` translate the eyeballs — if you re-key a clip, keep blinks on
  `lidL`/`lidR` so the runtime state machine still matches
  `../specs/animation_clips.md`.
* **Extra bones are optional.** Deleting `crown`, `handleL/R` (kiln), `lidKnot` (ribb),
  `finL/R` (zag), `core`/`frond*` (glim) or `ring*`/`tailFlap`/`legBL/BR` (rumble) removes
  only that flourish; the core 14 bones and the eight clips continue to work.
* **The badge bone must stay unweighted.** It is a mount point for the runtime number
  label (`../specs/badge_label.md`). If you weight geometry to it, a future value change
  will deform that geometry.
